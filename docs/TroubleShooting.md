# TroubleShooting — 치명적 문제 기록

공통 지침: [AGENTS.md](../AGENTS.md). 최신 작업: [HANDOFF](agents/HANDOFF.md).

## 작성 기준

- 크래시·프리즈·복귀 불가·데이터 손실/손상·보안 정보 노출·의도하지 않은 PC 종료·장시간 메모리 증가에 따른 운영 중단·배포를 막는 빌드 실패 등 치명적 문제를 발견하면 **해결 완료를 기다리지 않고** 항목을 만든다.
- 발견 에이전트가 문제와 재현 조건부터 기록하고 HANDOFF에서 항목을 연결한다. 안전한 우회가 있으면 함께 적고 관련 위험 작업을 중단한다. 다른 담당자의 파일을 임의로 되돌리지 않는다.
- 문제·원인·해결법은 각 1~3문장으로 간결하게 쓴다. 원인 미확정은 `조사 중` 또는 `추정`으로 표시하고 근거와 확인 방법을 적는다.
- 해결 후에는 수정 파일/커밋, 재현 조건에서의 검증 결과를 기록한다. 재현 검증 전에는 해결 완료로 표시하지 않는다. 단순 경고나 일반 TODO를 모두 장애로 분류하지 않는다.
- 실제 키·토큰·개인정보를 첨부하지 않는다. 비밀 노출이면 값 대신 노출 위치와 폐기/교체 필요 여부를 기록한다.

### TS-20261118-01 — 재실행 시 RFID 수신 포트 점유
- 발견/담당: 2026-11-18 Asia/Seoul 사용자 보고, Claude 단독, main/3d1a892, Windows Player.
- 문제: 프로그램을 껐다 다시 켜면 TCP 10123 수신이 `Listen failed ... AddressAlreadyInUse`로 실패해 리더가 연결되지 않는다. PC를 재부팅하거나 남아 있는 ComfyUI Python을 끝내야 풀린다.
- 원인: `Process.Start(UseShellExecute=false)`는 상속 가능한 핸들을 모두 자식에게 넘긴다. 앱이 띄운 ComfyUI 서버는 앱 종료 후에도 남도록 설계되어 있어, 물려받은 RFID 수신 소켓이 포트를 계속 붙잡았다. 에디터에서 수신 소켓을 연 뒤 자식 프로세스를 띄우면 수신을 닫아도 자식이 끝날 때까지 재수신이 실패하는 것으로 재현했다.
- 해결: 자식 프로세스를 핸들 상속 없이 실행하는 `Core.DetachedProcess`로 ComfyUI 서버와 운영 로그 감시기를 실행하고, RFID 수신·접속 소켓에 상속 금지 표시를 추가했다(`RfidTcpReaders`). 커밋 e210f10, b188d54.
- 검증: 에디터에서 두 방어를 각각 재현 조건으로 확인(자식이 살아 있어도 재수신 성공). Player 재실행 결과는 [deploy_self](validation/deploy_self/README.md).
- 재발 방지: 앱보다 오래 사는 자식 프로세스는 `DetachedProcess`로만 실행한다. 이전 버전이 띄운 서버가 남아 있는 PC는 교체 시 한 번 재부팅한다.

### TS-20261102-01 — Portable Comfy 내부 모델 코드 누락
- 발견/담당: COMFY-PORTABLE-001 패키징 사전검증, Codex 단독, main/3852ee6+기존변경, Windows. 아직 대상PC 배포 전.
- 문제: 별도8189 서버 시작 시 ModuleNotFoundError: comfy.ldm.models, 서버 준비 실패.
- 원인: robocopy /XD의 models basename 제외가 루트 가중치 폴더 외 comfy/ldm/models 코드까지 제외했다.
- 해결: Tools/ComfyUI/package_portable.py의 제외목록을 루트의 정확한 절대경로로 제한하고 재복사했다. 기존 설치파일/서버설정·프로세스/사용자빌드는 보존했다.
- 검증: 동봉환경8189서버 재시작·3실생성480RGBA/투명모서리·한글공백경로GPU연산 PASS. docs/validation/comfy_portable 증거 보존, comfy/ldm/models/autoencoder.py 존재확인. 실제새Windows/3060 후속.

상태: `조사 중 / 우회 적용 / 수정 후 검증 대기 / 해결`.

## 신규 항목 양식

ID는 `TS-YYYYMMDD-NN`으로 생성하고 중복을 확인한다. 상세 항목에 HTML 앵커 `<a id="TS-YYYYMMDD-NN"></a>`를 붙여 HANDOFF에서 `../TroubleShooting.md#TS-YYYYMMDD-NN`으로 연결한다.

```markdown
<a id="TS-YYYYMMDD-NN"></a>
### TS-YYYYMMDD-NN — 짧은 제목
- 발견: 일시/시간대, 에이전트, 브랜치/HEAD, 환경/빌드.
- 상태/담당: 조사 중 / 담당자.
- 문제: 관찰한 현상, 영향, 최소 재현 조건.
- 원인: 확정/추정/조사 중 구분, 근거 또는 다음 확인 방법.
- 해결법: 수정/우회 절차, 관련 파일·커밋 또는 미수정.
- 검증: 실제 수행한 재현/회귀 확인, 결과·증거, 남은 미검증.
- 재발 방지: 필요한 테스트/가드/운영 조치. 해당 없으면 없음.
```
