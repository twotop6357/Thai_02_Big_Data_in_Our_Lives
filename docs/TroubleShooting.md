# TroubleShooting — 치명적 문제 기록

공통 지침: [AGENTS.md](../AGENTS.md). 최신 작업: [HANDOFF](agents/HANDOFF.md).

## 작성 기준

- 크래시·프리즈·복귀 불가·데이터 손실/손상·보안 정보 노출·의도하지 않은 PC 종료·장시간 메모리 증가에 따른 운영 중단·배포를 막는 빌드 실패 등 치명적 문제를 발견하면 **해결 완료를 기다리지 않고** 항목을 만든다.
- 발견 에이전트가 문제와 재현 조건부터 기록하고 HANDOFF에서 항목을 연결한다. 안전한 우회가 있으면 함께 적고 관련 위험 작업을 중단한다. 다른 담당자의 파일을 임의로 되돌리지 않는다.
- 문제·원인·해결법은 각 1~3문장으로 간결하게 쓴다. 원인 미확정은 `조사 중` 또는 `추정`으로 표시하고 근거와 확인 방법을 적는다.
- 해결 후에는 수정 파일/커밋, 재현 조건에서의 검증 결과를 기록한다. 재현 검증 전에는 해결 완료로 표시하지 않는다. 단순 경고나 일반 TODO를 모두 장애로 분류하지 않는다.
- 실제 키·토큰·개인정보를 첨부하지 않는다. 비밀 노출이면 값 대신 노출 위치와 폐기/교체 필요 여부를 기록한다.

## 신규 항목 양식

ID는 `TS-YYYYMMDD-NN`으로 생성하고 중복을 확인한다. 상세 항목에 HTML 앵커 `<a id="TS-YYYYMMDD-NN"></a>`를 붙여 HANDOFF에서 `../TroubleShooting.md#TS-YYYYMMDD-NN`으로 연결한다.

```markdown
<a id="TS-YYYYMMDD-NN"></a>
### TS-YYYYMMDD-NN — 짧은 제목
- 발견: 일시/시간대, 에이전트, 브랜치/HEAD, 환경/빌드.
- 상태/담당: 조사 중 / 담당자.
- 문제: 관찰한 현상, 영향, 최소 재현 조건.
- 원인: 확정/추정/조사 중 구분, 근거 또는 다음 확인 방법.
- 해결법: 수정/우회 절차, 관련 파일·커밋 또는 미수정.
- 검증: 실제 수행한 재현/회귀 확인, 결과·증거, 남은 미검증.
- 재발 방지: 필요한 테스트/가드/운영 조치. 해당 없으면 없음.
```
