# 타이틀 배경 영상

`Assets/Resources/Videos/c02.mp4`는 0_Idle의 `ImageUI/IntroVideo`(`IdleVideoBackground`)에서 소리 없이 반복 재생된다. 바로 아래에는 정지 배경 `Intro_bg`가, 위에는 로고·문구·팝업이 있다. 첫 프레임이 준비되기 전이나 재생에 실패하면 정지 배경이 보인다.

IDLE-LOOP-001(2026-11-11)에서 루프 지점이 튀는 문제를 고쳤다. Thai_04의 c04와 같은 원인·같은 방식이다. 측정 근거는 [validation/idle_loop](validation/idle_loop/)에 있다(`results.json`, `seam_sheet.png`, `still_cmp.png`).

## 원인

받은 영상은 H.264 Main, 31.8 Mbps, 1920×1080, 30fps, 120프레임(4초)이었다. 키프레임은 30프레임마다(0·30·60·90) 있고, B프레임은 없다. 색상 태그와 오디오도 없다.

1. **파일**: 0번은 키프레임이고 119번은 P프레임이 이어지며 압축 노이즈가 쌓인 끝이다. 그래서 정지 배경의 입자가 이음매에서 한꺼번에 바뀐다. OpenCV로 전체 프레임을 디코딩해 영역별 평균 변화량(0~255 레벨)을 쟀다.

   | 영역 | 평소 한 프레임 | 키프레임(30·60·90) | 이음매 119→0 |
   |---|---|---|---|
   | 정지 배경 | 0.030 (중앙값 0.008) | 0.21~0.33 | **0.644** |
   | 움직임 | 2.16 (최대 2.48) | 2.09~2.34 | 2.65 |

2. **재생**: `VideoPlayer.isLooping`은 실행 중인 디코더를 0번으로 되감는다. Unity Play 모드에서 표시 텍스처를 매 렌더 프레임 읽었다(60fps, 60초, 루프 15회).
   - 119번이 평소 33ms가 아니라 중앙값 50ms(최대 90ms) 동안 머물렀다.
   - 15번 중 1번은 119 다음에 8프레임 전 화면(111)이 16.5ms 보였다.
   - 정지 배경 crop의 이음매 변화는 1.13으로, 평소 0.05의 약 23배였다.
   - 빈 텍스처는 없었다.

## 영상 재인코딩

ffmpeg 9.0.2(시스템 미설치, 임시 폴더의 `imageio-ffmpeg` 실행 파일)로 다음 명령을 실행했다. 프레임 수가 120이라 trim·`-g` 값은 c04와 같다.

```bash
ffmpeg -stream_loop 2 -i c02_source.mp4 \
  -vf "hqdn3d=0:0:6:6,trim=start_frame=120:end_frame=240,setpts=PTS-STARTPTS" \
  -c:v libx264 -preset slow -profile:v high -pix_fmt yuv420p -crf 10 \
  -g 120 -keyint_min 120 -sc_threshold 0 -bf 0 \
  -x264-params "colorprim=bt709:transfer=bt709:colormatrix=bt709:ipratio=1.0:mbtree=0" \
  -color_range tv -an -movflags +faststart c02.mp4
```

- 입력을 세 번 이어 붙이고 가운데 120프레임만 남긴다. 그래서 시간 노이즈 제거가 119→0을 다른 프레임 사이와 똑같이 다룬다.
- 루프당 키프레임 1개, B프레임 없음, I/P 같은 품질(`ipratio=1.0`, `mbtree=0`)로 배경이 이음매에서도 안정된다.
- BT.709 태그로 Unity의 "Color primaries 0 is unknown" 경고가 사라졌다.

| 항목 | 원본 | 재인코딩 |
|---|---|---|
| 형식 | H.264 Main, 31.8 Mbps | H.264 High, 14.5 Mbps, BT.709 tv |
| 키프레임 | 0·30·60·90 | 0 |
| 크기 | 15,908,557 B | 7,258,378 B |
| 정지 배경 평소/이음매 | 0.030 / 0.644 | 0.007 / **0.174** |
| 움직임 평소(최대)/이음매 | 2.16(2.48) / 2.65 | 1.99(2.15) / 2.41 |

- 화질은 원본 대비 Y PSNR **50.0 dB**, 평균 차이 0.007 레벨이다. 노이즈 제거만 하면 50.6 dB, 인코딩 손실만 보면 57.4 dB다. RGB 기준으로는 전체 45.0, 움직임 영역 41.9, 정지 배경 47.0 dB다.
- ffmpeg `psnr` 필터는 35.4 dB를 냈다. 프레임 번호로 맞춰도 같아서, 두 파일의 색 범위 태그 차이 때문에 필터가 변환을 거친 값으로 추정한다. Y 평면을 직접 비교한 값을 기준으로 삼았다.
- 움직임 영역은 원본에서도 이음매(2.65)가 다른 단계(최대 2.48)보다 약간 크다. 애니메이션 자체의 끝-처음 차이로, 인코딩으로는 바꿀 수 없다.

## 정지 배경

새 영상의 첫 프레임과 `Intro_bg`를 Unity 안에서 같은 Blit 경로로 읽어 비교하니 평균 10.5 레벨 차이가 났다(99% 지점 204). 구도는 같지만 인물·카드 위치가 몇 픽셀 어긋나고 하늘 밝기가 달라, 영상이 나타나는 순간 화면이 튈 수 있었다. 그래서 `Intro_bg.png`를 Unity가 디코딩한 첫 프레임으로 다시 만들었고, 다시 비교한 차이는 **0.0**이다. 영상에는 로고가 없으므로 로고를 따로 두는 구성은 그대로다. 읽기 경로가 PNG 원본 값을 그대로 돌려주는지(차이 0.0)도 먼저 확인했다.

## 재생 코드

`IdleVideoBackground`는 `isLooping` 대신 VideoPlayer 2개(씬의 1개와 실행 중 추가하는 1개)를 번갈아 쓴다. 클래스·직렬화 필드 `clip`·씬 구성은 그대로다.

1. 대기 플레이어는 `Stop` 후 렌더 텍스처를 투명하게 비우고 다시 `Play`한다.
2. `frameReady`를 받은 다음 렌더 프레임에서 `Pause`한다. 그 사이 `frame > 0`이 되었으면 다시 준비한다.
3. 멈춘 뒤 1×1 `AsyncGPUReadback`으로 알파를 확인하고, 비어 있으면 다시 준비한다. Unity가 가끔 첫 프레임을 그리지 않기 때문이다.
4. 마지막 프레임이 한 프레임 길이(33ms)만큼 보이면 화면을 넘긴다. 다음 플레이어가 아직 준비되지 않았으면 마지막 프레임을 유지한다.
5. **이 프로젝트에서 추가한 보정**: 화면을 넘긴 렌더 프레임에서만 재생 속도를 1.5배로 두고 다음 프레임에 1배로 되돌린다. 렌더 프레임 순간에 새 플레이어를 시작하면 영상 프레임 경계(33ms)가 렌더 순간(16.7ms 간격)과 정확히 겹친다. 그러면 프레임 시간의 작은 흔들림에도 한 프레임이 16ms·50ms로 번갈아 보인다. 이 보정은 경계를 렌더 프레임 반 개만큼 옮긴다.
   - 보정 전(200초, 루프 50회): 렌더 1개·3개 동안 보인 프레임 약 22%
   - 보정 후(60초, 루프 15회): 2.6%, 기존 단일 재생의 약 2%와 같은 수준
6. 렌더 텍스처(1920×1080 2개, 1×1 2개)는 타이틀에 들어올 때 만들고 떠날 때 해제한다.

## 검증 (Unity 2022.3.62f3 Editor, Game 1920×1080, 60fps 제한)

임시 런타임 프로브(작업 후 삭제)를 썼다. 실제로 화면에 표시되는 RawImage 텍스처를 매 렌더 프레임 끝에 작은 RenderTexture로 Blit하고 `AsyncGPUReadback`으로 읽었다. `VideoPlayer.frame`·`isPlaying`·`isPaused`도 함께 기록했다. 표시 프레임은 별도 플레이어로 120프레임을 하나씩 멈춰 디코딩한 Unity 기준 이미지와 맞춰 판별했다. 모든 기록 프레임이 기준과 차이 0.0으로 일치했다. Editor는 제한이 없으면 약 1,000fps로 돌아서, 배포본의 수직 동기(60Hz)를 흉내 내려고 기록 중에만 `targetFrameRate`를 60으로 두었다가 되돌렸다.

| 항목 | 수정 전(isLooping) | 최종 |
|---|---|---|
| 기록 | 60초, 루프 15회 | 84초, 루프 21회(사용자 지시로 200초 전에 종료) |
| 순서 어긋남(뒤로 튐) | 1회(119→111) | **0** |
| 빈 텍스처·영상 숨김 | 0 | **0** |
| 마지막 프레임 유지 | 중앙값 50ms, 최대 90ms | 중앙값 34ms, 최대 51ms¹ |
| 평소 프레임 유지 | 중앙값 33.3ms, 99% 35.7ms | 중앙값 33.3ms, 99% 38.3ms |
| 화면 전체 변화 118→119 / 119→0 / 0→1 | 0.57 / **1.09** / 0.59 | 0.54 / **0.72** / 0.45 |
| 정지 배경 crop 평소 / 이음매 | 0.05 / 1.13 | 0.021 / 0.68 |

¹ 프로브가 전체 해상도(8MB)를 캡처하던 이음매 2곳은 렌더 프레임이 32~47ms로 늘어 75ms·22ms와 0→2 건너뜀이 1번 생겼다. 측정 도구 부하로 보고 제외했다.

- 같은 교대 로직을 보정 전 상태로 200초(루프 50회), 보정 후 60초(루프 15회) 더 기록했다. 모두 순서 어긋남 0, 빈 텍스처 0이다. 교대 방식 누적은 344초, 루프 86회다.
- 이음매 변화: 화면 전체의 119→0은 0.72로 앞뒤 단계(0.54·0.45)의 1.3~1.6배다. 수정 전 1.09보다 작고, 남은 차이는 대부분 움직임 윤곽이다. 정지 배경에서 가장 크게 바뀌는 64px 영역은 0.68로 평소(0.021)보다 크지만 1레벨 미만이다. `seam_sheet.png`의 25배 확대 차이 이미지에서 수정 전에는 화면 전체에 배경 입자가 보이고, 수정 후에는 배경이 거의 검다.
- 화면 수명: 타이틀 렌더 텍스처 4개 → 게임 화면 0개 → 홈 복귀 후 4개, 다시 재생. 콘솔 오류 0.
