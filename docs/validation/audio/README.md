# AUDIO-001 — 전역 오디오 매니저

2026-11-05 Asia/Seoul · Claude 단독 구현·검증 · main/3852ee6 + 기존 미커밋 보존. 커밋/push/배포 빌드 없음. 교차 검증 없음.

## 동작

`Core.AudioManager`는 영속 `GameManager` 오브젝트에 처음 사용할 때 붙고 `GameManager.Audio`로 접근한다. `Resources/Audios/confirm`·`home`을 재생하며 씬 전환에도 끊기지 않는다. 사운드 파일이 없으면 영문 오류만 남기고 소리 없이 진행한다.

| 소리 | 재생 시점 |
|---|---|
| confirm | 타이틀→게임, 그룹→선택 패널, 선택→결과, 광고→영상(실패 후 재시도 포함) |
| home | 5초 홈, 영상 종료 팝업의 버튼, 블록을 모두 뺀 종료, 무입력 시간 초과 |
| 없음 | 언어 전환, 이미지 생성 시작, 조건 미달 버튼 입력, 블록 놓기, 영상 자연 종료 |

- 그룹→선택 자동 진행(비그룹 블록 인식)은 버튼과 같은 전환이므로 confirm을 재생한다. 사용자 미확정 기본값.
- 시간 초과와 블록 제거는 버튼 입력이 아니어도 "최초 화면 회귀"이므로 home을 재생한다.
- 복귀 시 전체 AudioSource를 끄는 `StopSessionMedia`에서 이 매니저의 소스는 제외한다.

## 실제 검증

Unity 2022.3.62f3 / Windows Editor. `runtime.json`: Play **32항목 PASS**. 재생 로그로 종류·횟수를, `AudioListener.GetOutputData`로 실제 믹서 출력(7개 시점 peak 0.325~0.330)을 확인했다. 스피커 청취는 하지 않았다. 재생 시점 표의 블록 전부 제거 종료는 같은 경로라 별도 실행하지 않았다.

이 실행 뒤 UI-ADHINT-001이 광고 입력 시점을 바꿨다. 오디오 코드는 그대로이고 광고→영상 전환은 `../ad_hint/runtime.json`에서 다시 통과했지만, 이 소리 검증 자체는 재실행하지 않았다.

무입력 복귀가 설정값 30초가 아닌 56.9초에 일어났다. `InactivityTimer`가 모든 Input System 이벤트에 초기화되므로 검증 중 이 PC의 입력 때문으로 **추정**한다(미확인). 오디오와 무관한 기존 동작이다.
