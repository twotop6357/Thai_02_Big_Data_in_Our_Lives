# UI-ATTN-001 — 블록 인식 화면의 안내 연출

2026-11-05 Asia/Seoul · Claude 단독 구현·검증 · main/3852ee6 + 기존 미커밋 보존. 커밋/push/배포 빌드 없음. 교차 검증 없음.

## 동작

그룹 화면과 선택 화면에 같은 규칙을 적용한다. 그룹 화면은 칸이 하나이므로 무작위 대상도 그 칸뿐이다.

- **빈 칸 글자**: 블록 변화 없이 3초가 지나면 비어 있는 칸 중 무작위 한 칸의 글자만 `DOPunchScale`로 18% 커졌다 돌아온다(0.55초). 입력이 없으면 3초마다 다시 뽑아 반복한다. 블록을 놓거나 빼면 대기 3초를 처음부터 센다.
- **초과 블록**: 그룹·제품 2개 이상, 색 3개 이상이면 이미 표시된 해당 블록이 `DOPunchAnchorPos`로 좌우 10px 진동한다(0.45초). 초과가 시작되면 곧바로 재생하고 유지되면 3초마다 반복한다. 색 초과는 표시된 색 두 칸이 함께 진동한다. 초과 블록과 빈 칸 글자의 주기는 서로 독립이다.
- 두 연출 모두 입력을 잠그지 않는다. 생성 중, 씬·패널 전환 중, 다른 연출이 입력을 잠근 동안에는 재생하지 않는다. 전환 시작과 화면 비활성화 때 Tween을 끊고 크기·위치를 원래대로 되돌린다.

"즉시"의 실제 값: 그룹 화면에서 두 번째 그룹이 올라오면 기존 계속 안내의 페이드(입력 잠금)가 끝난 뒤인 약 0.27~0.28초에 시작한다. 선택 화면의 제품 초과처럼 안내 페이드가 없으면 0.2초 안에 시작한다.

## 글자 분리

웹 칸 PNG는 불투명 단색 채우기 위에 글자가 구워져 있어 글자만 움직일 수 없다. 원본 PNG 6개는 바꾸지 않고 다음을 추가했다.

- `Tools/UI/extract_slot_labels.py`: 원본에서 글자만 뽑은 같은 크기의 투명 `*SlotLabel_en/th.png` 6개와 단색 `SlotLabelCover.png` 1개를 만든다. 따라서 이 7개는 웹 ZIP 원본이 아니라 **파생본**이다.
- 칸 아래에 `SlotLabelCover`(칸의 12~88% 영역, 구워진 글자를 가림) > `SlotLabel`(칸과 같은 크기)을 두고, 블록이 놓이면 함께 숨긴다. 글자 스프라이트는 언어 JSON의 새 항목으로 전환한다.
- 분리본 합성과 원본의 채널 차이 최대 0.94/255(`label_split.json`). 대기 상태 그룹 칸을 이전 캡처와 비교한 결과 RMSE TH 0.114, EN 0.13, 최대 4/255(`rest_pixels.json`).

## 실제 검증

Unity 2022.3.62f3 / Windows Editor / Game 1920×1080. 블록은 `RfidReaderHub`에 직접 넣었다.

- EditMode **139/139 PASS**. 신규: 종류별 초과 판정, 빈 칸 3초 대기·재시작·반복, 초과 즉시 재생·3초 반복·해소, 잠금 중 보류.
- `runtime.json`: Play **64항목 PASS**, 양언어. 빈 칸 반복 간격과 초과 블록 반복 간격 실측 3.00~3.02초, 무관한 칸 정지, 세로 이동 없음, 선택 화면에서 한 번에 글자 한 칸만 재생되고 대상이 바뀜, 칸 이동 전 Tween 정리, 화면 비활성화 복구, 5초 홈 복귀.
- `slots_regression.json`: `verify_slots_runtime`을 증거 경로만 바꿔 재실행(스크린샷 생략)한 칸 회귀 **152항목 PASS**, 양언어, 칸 이동 0.503/0.500초. 항목 수에는 이동 중 프레임별 반복 검사가 포함돼 프레임 수에 따라 달라진다.
- 무작위성 검사는 대상 칸이 2종 이상 나오는지만 본다. 분포는 측정하지 않았다.
- 검증 스크립트의 조건 오류로 세 번 중단됐고(안내 페이드 잠금 오판, 0점 통과 중복 계수, 배치 연출 대기 부족) 앱 코드가 아니라 스크립트를 고쳤다.
